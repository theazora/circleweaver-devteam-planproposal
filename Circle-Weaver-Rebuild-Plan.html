Rebuild plan proposal

We're modernizing Weaver as Circle Weaver: new React UI for the screens that matter most, same Java backend, mobile-first. Not a full rewrite.

1. What this project is

Brand, UX, and engineering together: rebrand to Circle Weaver, redesign the priority screens for phone and laptop, and ship them in React (Next.js) on the APIs we already have.

TeamFocus
BrandLogo, icons, colors, Circle Weaver identity
UX/UIResearch, wireframes, usability tests, hi-fi prototypes
DevWorking React modules wired to existing Java APIs
A11yWCAG 2.1 AA, keyboard, screen readers, fast loads
Keep the model: Sites (orgs) hold workspaces (circles). Members participate. Stewards edit and manage. Meetings, discussions, decisions, docs, and action items stay.

Meetings have to work both ways: quick on a phone, solid for notetaking on a laptop.

2. What we build first

UX prototypes drive what ships. Confirm priorities at kickoff.

#AreaWhy
P0App shell + loginEverything else sits on this
P1MeetingsHero feature; kills the old separate mobile meeting UI
P2Workspace homeWhere people land every day
P3User homeYour spaces, alerts, entry point
P4RolesMembers vs stewards, if time allows
LaterAdmin, billing, process appsLeave on the old UI for now

After the semester: video meetings, live presence, richer feeds, AI helpers.

Most of the current UI lives under spring2/ (user home, workspace pages in jsp/, site admin). We'll dig into those folders to map screens to APIs and decide what gets rebuilt first. The old mobile-only flow in spring2/wmf/ (separate *.wmf meeting pages) goes away; meetings move into one responsive React module instead.

4. What we have today

Solid Java 21 / Spring backend (about 118 JSON endpoints, file-based workspace storage). The frontend is the problem: AngularJS inside hundreds of JSPs, plus a separate mobile meeting flow that doesn't match the desktop app.

LayerTodayIssue
UIJSP + AngularJS 1.xOld stack, hard to maintain
LayoutsMany copy-pasted wrappersBugs and drift
MobileSeparate WMF pagesTwo products in one
Live updatesEmail + refreshFeels dated
DataXML/JSON files per workspaceFine to keep for a UI rebuild

Marketing site stays its own thing. The new app is only the logged-in product.

7. Backend approach

No rewrite. React talks to the same *.json endpoints Angular uses today. We add a thin Next.js proxy so cookies and CSRF are less painful, plus a few small Java fixes.

Leave alone

  • Java domain logic, roles, meetings, workspace lifecycle
  • SSOFI login
  • File storage and Mongo for email

Add this term

PieceWhy
Next.js BFF proxyBrowser hits Next; Next hits Tomcat
CSRF + secure cookiesNeeded before any pilot

API map per screenSo everyone knows which endpoints matter

Skip this term: Postgres migration, new API versions, WebSockets, video, full security cleanup.

9. Asks and later ideas

Need from backend before pilot

  • CSRF token endpoint
  • HttpOnly / Secure cookies
  • Structured JSON errors

Ops notes

  • SSO / login email: messages from the identity provider (SSOFI) sometimes land in spam. Worth flagging for users and reviewing sender/reputation with backend.
  • MongoDB: used today mainly for the email archive (weaver.email). If we improve notification delivery or dig into bounced/spam mail, that's likely where we look.
