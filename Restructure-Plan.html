2. Suggested weekly workflow

This is the loop that has worked well for me on repos like this, especially while a lot of us are still getting comfortable.

  1. Pick this week’s files from the list (better not to freestyle here).
  2. Move or copy into the new place. Never delete the old copy yet.
  3. Team check-in: show what moved, click through, confirm it still runs.
  4. Only after check-in: archive old copies, tidy names, small upgrades.
  5. Confused? Write it in a shared questions.md instead of guessing.

Safe move loop

flowchart TD
  Pick[Pick this week's files] --> Move[Move / copy to new home]
  Move --> Keep[Leave old files in place]
  Keep --> Check[Team check-in]
  Check -->|Still works| Upgrade[Then archive or upgrade]
  Check -->|Broken| Fix[Fix together, do not delete yet]
  Fix --> Check

Week 8 (Nov 3-9): Stakeholder questions + handoff prep

By now the code should be slimmer. This week is partly waiting on people outside the team, so I’d use that time to ask good questions and lock the backbone.

Network / login / profiles: questions worth asking stakeholders

From my experience with this kind of stack, I’d look at moving from SSOFI/SSO toward OAuth (with one base account that can link Google, Microsoft, and other providers) because OAuth is a standard pattern newer teammates already know, works internationally (including Dutch users), and is usually simpler to maintain in a React/Next app than keeping a separate SSOFI login WAR in the loop. Longer term, exploring OAuth instead of staying on SSOFI forever also makes sense: it’s a common international login standard, easier to teach on this team, and lets people connect multiple platforms to one base account without running a separate identity app.

  1. Login: keep current SSO / SSOFI, or move to simpler OAuth (Google / Microsoft / etc. linked to one base account)?
  2. Profiles: today a profile is very dry, almost nothing to showcase someone. What should a clean profile include (bio, skills, posts, learning completed, facilitator info)?
  3. Hosting: where do app, login server, and marketing pages live today, and what can we change without breaking production?

Capture answers in docs/stakeholder-answers.md so Nov 13 isn’t blocked by guessing.

M4 checkpoint: repo cleaned/archived per plan, README works for a new teammate, questions sent, team ready for wireframes.

7. After Nov 13: design steers us

My suggested handoff point. After this, UI/UX and marketing set the visual direction and we build on the backbone we cleaned.

Handoff → direction

flowchart LR
  Backbone[Until Nov 13:\nslim code · solid Next backbone] --> Handoff[Nov 13\nwireframes and ideas]
  Handoff --> Direction[UI/UX + marketing\nset visual direction]
  Direction --> Build[Late Nov: implement\ndesigns on our backbone]

We won’t know exact screens, colors, or marketing content until that handoff. Until then, I’d keep our focus on slim code, updated infrastructure, and a solid backbone. New moving parts come later.

If there’s idle time in late Nov / Dec while waiting on feedback: optionally improve meetings with a proper Zoom API link flow (better than pasting links by hand). A full built-in WebRTC meeting service is a future idea only if stakeholders want it, more realistically next year. Not part of this 8-week suggestion. Cleaner, faster workflows come first.
